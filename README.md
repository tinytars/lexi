# health-dashboard

Per-client health dashboard (blood, body-composition, imaging) — a Svelte 5 SPA on Cloudflare Pages.
Each patient's record lives in its own encrypted blob in R2, decrypted **in the browser** under a
per-vault DEK that is wrapped per principal into an envelope in D1 (W44). Plaintext never touches the
server, with the deliberate exceptions listed in `SECURITY.md`. The Finding and personalized ranges
are generated by Claude — from the browser through a session-gated relay, or from the CLI directly.

## Local dev

`npm` is not on the default `$PATH` on Pablo's MacBook (Node lives under
`/Users/finca/homebrew/bin/`). In bash, either prefix each command:

```bash
cd apps/health-dash-web
PATH="/Users/finca/homebrew/bin:$PATH" npm install
PATH="/Users/finca/homebrew/bin:$PATH" npm run dev
```

…or add the directory to your bash profile once so plain `npm` works afterward:

```bash
echo 'export PATH="/Users/finca/homebrew/bin:$PATH"' >> ~/.bash_profile
source ~/.bash_profile
```

`npm run dev` serves the dashboard at `http://localhost:5173`. Sign in with an account email +
password (W44); the committed `records/public/data-{id}.enc` slices are what it reads. There is no
sample blob and no demo passphrase — the repo once shipped one, and a served blob with a documented
passphrase is precisely the shape this app spent a milestone removing.

### Editing patient input in the browser (W5 + W6)

Unlocking a client shows an **Edit** button that opens a tabbed form over the user-authored
fields (profile, conditions/diseases, medications/supplements, correlations, study,
plan/decisions). **Save** re-encrypts in the browser, then persists via a `VaultSink`:

- **`npm run dev`** writes `public/data-<id>.enc` straight to disk via a dev-server endpoint
  (`/__save-vault`, dev-only — absent from the deployed build).
- **Deployed build** PUTs the encrypted blob to R2 via `/api/vault/<id>` (W6), so edits
  persist from anywhere incl. a phone. Guarded by the per-client bearer + Cloudflare Access.

Markers stay read-only (ingestion owns them). After editing inputs, re-run the relevant
`npm run ingest -- … --refresh-*` to regenerate the Finding (a "Finding stale — regenerate via
CLI" badge flags when needed). The CLI **auto-syncs with R2** (W6e): it pulls the latest blob
before loading and pushes after writing, so a deployed/phone edit is picked up automatically and
a regen never clobbers it (`--no-sync` to skip when offline). Setup + the audit trail: `AUTH.md`;
architecture: `VAULT.md`.

## Ingest CLI

Run from inside `apps/health-dash-web/`:

```
# Initialize a new vault (one time)
npm run ingest -- --init --client a --display-name "Client A"

# Add marker history from a healthmatters.io XLS export
npm run ingest -- ./client-a.xlsx --client a

# Manage the watchlist (the markers that matter most for this client)
npm run ingest -- --client a --add-marker "Vitamin D"
npm run ingest -- --client a --remove-marker "Ferritin"
```

The CLI prompts for the passphrase (no echo). On success it writes `records/roster.enc` plus the touched `records/public/data-<id>.enc`. Raw XLS files are gitignored — do not commit them.

### XLS format expected

The parser looks for these columns (case-insensitive, partial match):

- **marker / biomarker / test / analyte / name** — required
- **date / collected / drawn / test date** — required
- **value / result / reading** — required
- **unit / units** — optional
- **reference range / range / interval** — optional (parses `30-100`, `< 1.0`, `> 0.5`)

If your healthmatters.io export uses different column names, edit `src/lib/xlsx.ts:HEADER_MATCHERS`.

## Deploy

Cloudflare Pages project pointing at this repo:

- Root directory: `apps/health-dash-web`
- Build command: `npm run build`
- Output: `dist`
- Custom domain: set per your zone
- Cloudflare Access policy: email-match to your address (defense in depth)

After each `npm run ingest` run, commit the changed `records/` artifacts and push — Pages redeploys automatically.

### Web-chat secrets (`/api/chat`)

Full step-by-step runbook: **`AUTH.md`**. In short, the chat Pages Function needs two secrets,
set once per project. Cloudflare Access (above)
and the bearer guard are layered — Access keeps strangers off the URL; the bearer keeps the
endpoint from being an open Anthropic relay.

1. **Provision a _distinct_ Anthropic API key** for chat — on a separate budget/limit from
   the CLI pipeline's key, so the web user can never exhaust the Finding's credits.
2. `npx wrangler login` (wrangler is a devDependency — run via `npx`, from `apps/health-dash-web/`)
3. `npm run allowlist` → copy the printed value (the comma-joined per-client bearer hashes,
   one per `public/data-<id>.enc`).
4. From `apps/health-dash-web/`:
   ```
   npx wrangler pages secret put ANTHROPIC_API_KEY   # paste the distinct key
   ```
5. Push (Functions ride the git-integration deploy). Verify: `curl -X POST
   https://<domain>/api/chat -H "authorization: Bearer <derived>" -d '{"question":"hi","context":{}}'`
   → `200`; an unknown bearer → `401`.

When a new client slice is added (`data-<id>.enc`), re-run `npm run allowlist` and re-set
`VAULT_TOKEN`. Local dev uses `.dev.vars` (gitignored) instead of these secrets —
`npm run dev:functions`.

### Remote vault persistence (`/api/vault`, W6)

So edits saved from a phone persist without your laptop, per-client blobs are stored in an R2
bucket behind `/api/vault/[id]` (a Pages Function that only moves already-encrypted blobs). The
deployed build saves to R2; `vite dev` still saves to disk. One-time setup (bucket +
`VAULT_TOKEN`) and verification are in **`AUTH.md` § W6**; the endpoint contract is in `API.md`.
The bucket binding is committed in `wrangler.jsonc`.

## Testing (verifiable from the CLI)

`npm run test:all` runs unit (`vitest`) + e2e (`playwright`). The standing rule (W10):
**every behavior is provable headlessly — nothing merges that can only be checked by clicking.**
API → a vitest test importing the Function handler (Anthropic mocked) + a `curl` contract;
UI behavior → a Playwright spec (stub `/api/chat` with `page.route`; never write
`public/data-*.enc` in a test); pure logic → a unit test. Ship the matching coverage with each
feature. Full rule + the per-layer table: **`API.md` § Verifiability** and
`docs/plans/10-w10-headless-verifiability.md`.

**Green-before-main gate.** A tracked `pre-push` hook (`.githooks/pre-push`, repo root) runs
`build` + `test:all` and **aborts any push that updates `main`** if either fails; pushes to
other branches are not gated. GitHub branch protection isn't available on this private repo
without GitHub Pro, so this local hook is the enforcement point for the CLI merge-to-main flow.
Enable once per clone: `git config core.hooksPath .githooks`. Emergency bypass:
`git push --no-verify`.

## Security model

- Encryption: AES-GCM-256 with a key derived from your passphrase via PBKDF2-SHA256, 200k iterations.
- The repo is **private** — encrypted blobs in git plus access-controlled GitHub plus the passphrase form three layers of defense.
- Cloudflare Access in front of the live URL means random visitors never see the lock screen.
- The ingest CLI keeps plaintext only in memory for the duration of the run.
- Forgetting the passphrase = data is unrecoverable. There's no backdoor. The Recovery section below records the current passphrase so future-you isn't locked out.

## Recovery

If you're coming back to this after months and can't remember how to operate the pipeline, this section is the one to read.

**Roster passphrase**: `PASSPHRASE` (or `ROSTER_PASS`) in `~/.claude/infra/cloud/credentials/health-dash.env` — decrypts `records/roster.enc`, the display-name directory. This line used to print the literal, on the theory that future-you would need it. That made a *served* blob openable by anyone who could read this file, which is the one thing a passphrase must never be; the roster has since moved out of `records/public/` as well. The credential file is the single source — see `~/.claude/CLAUDE.md`.

**Per-client vaults** are HD1 v2: a per-vault DEK wrapped per device via ECDH, unwrapped from the committed org-recovery sidecar (`data-<id>.dek.enc`) — not a passphrase, and specifically not the client id, which is what v1 used before the W44 envelope cutover.

**Client ids are opaque (G1)** — the lowercased account id, not a name; the name lives on as `displayName` inside the ciphertext. `--client Pablo` still works: the CLI resolves a display name to its id at the boundary.

**Refreshing personalized ranges and the AI Finding** (both call Anthropic):

The `ANTHROPIC_API_KEY` and the vault `PASSPHRASE` are **not stored in this repo** — they live in
the plover-context credentials repo. Source them (override the dir with `PLOVER_CREDENTIALS_DIR`):

```
CRED="${PLOVER_CREDENTIALS_DIR:-$HOME/.claude/infra/cloud/credentials}"
set -a; . "$CRED/anthropic.env"; . "$CRED/health-dash.env"; set +a   # ANTHROPIC_API_KEY + PASSPHRASE

# personalized ranges for one client's watchlist
npm run ingest -- --client Pablo --refresh-ranges --force

# AI Finding (Progression / Possible findings / Treatment suggestions)
npm run ingest -- --client Pablo --refresh-finding --force

# both in one decrypt/encrypt cycle
npm run ingest -- --client Pablo --refresh-ranges --refresh-finding --force
```

`--force` regenerates even if the relevant input hash (`factorsHash` for ranges, `inputsHash` for the Finding) matches the stored value. Drop it for the cheap skip-if-unchanged behavior.

**Machine-specific gotchas on Pablo's MacBook**:

- Node lives at `/Users/finca/homebrew/bin/` (custom homebrew prefix), not on the default `$PATH`. Prepend it: `PATH="/Users/finca/homebrew/bin:$PATH"`.
- Node 25 can't verify api.anthropic.com without an extra CA bundle. Set `NODE_EXTRA_CA_CERTS=/etc/ssl/cert.pem`. Without this the SDK reports a bare "Connection error." while curl works fine.

So the full bulletproof one-liner from a fresh shell is (sourcing the passphrase + key from the
plover-context credentials repo rather than inlining them):

```
CRED="${PLOVER_CREDENTIALS_DIR:-$HOME/.claude/infra/cloud/credentials}"
set -a; . "$CRED/anthropic.env"; . "$CRED/health-dash.env"; set +a
PATH="/Users/finca/homebrew/bin:$PATH" \
NODE_EXTRA_CA_CERTS=/etc/ssl/cert.pem \
npm run --prefix apps/health-dash-web ingest -- \
  --client Pablo --refresh-ranges --refresh-finding --force
```

**After any refresh** the script rewrites `records/roster.enc` plus every `records/public/data-<id>.enc` (each slice picks up a fresh IV even when its plaintext didn't change). If only one client was refreshed, restore the untouched slices before committing: `git checkout -- records/public/data-<other>.enc`. Then commit and push — Cloudflare Pages redeploys automatically.
